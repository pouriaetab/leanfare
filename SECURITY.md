# Security

Leanfare runs on your own computer and listens on 127.0.0.1 only. It keeps your provider keys in the macOS Keychain (elsewhere, in a file only you can read), sends each key only to its own provider, and sends nothing anywhere else: no telemetry.

It reads usage numbers, never your words: from Claude Code's and Codex's log files it takes only the model, the time and the token counts. The MCP server's `delegate` tool reads only the files it is handed, refuses files that hold secrets (`.env` files and their kin, private keys, credential and token files, and anything in `.ssh`, `.gnupg`, `.aws`, `.git`, a keychain or Leanfare's own folder), and sends them only to the model it picks.

A plan's parts get only the files they name, with the same refusals; a folder's dotfiles and links are left out. A part on Codex is the exception: Codex reads what it needs itself, as when you use it, so these refusals do not apply to it. The answers are written only in the project's `.leanfare` folder, never through a link. Paid parts run only with your yes or within the amount you set. Plan by itself changes only Leanfare's own lines in `CLAUDE.md`, `AGENTS.md` and `GEMINI.md`, its own subagent file and its own hook entry, and keeps each file's links and permissions.

Codex runs a plan's parts only while the switch in Settings is on (checked again when each part runs) and only when it is signed in with ChatGPT. It runs them in its read-only sandbox with its approvals off (`--sandbox read-only`, `approval_policy="never"`), and without your MCP servers, ChatGPT's apps, plugins, hooks or the browser, which act outside the sandbox: it can read files but changes nothing. Stop ends the commands it started too. Leanfare asks Codex only how it is signed in and never reads its sign in. A local model is downloaded only after your yes: a press in the app, or Leanfare's question in your app (an app that cannot show it asks you in the chat first). Grades keep the model, the kind of work, the effort, the grade, who gave it and when, never the words.

Gemini CLI runs a plan's parts only while its switch in Settings is on and it is signed in with your Google account: one prompt at a time in its plan mode (`--approval-mode plan`), where anything that would change a file or run a command is refused, in the folder of the part's files (an empty one when it names none). Google's terms for a free account let people read what is sent, so a private plan never goes there.

Claude's helpers: the leanfare-level mod and Claude Code's hook change only the model a helper runs on, never its task, tools or permissions; a fork keeps the chat's own model. With Leanfare not running, or anything going wrong, they change nothing and the helper runs as Claude chose. Leanfare keeps no helper's words, only its kind of work, effort, model and token counts.

To report a security problem, use GitHub's private vulnerability reporting on this repository (Security, Report a vulnerability) rather than a public issue. Please include the version (`leanfare --version`) and the steps to see it.
